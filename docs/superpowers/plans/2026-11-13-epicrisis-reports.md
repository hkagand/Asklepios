# Epicrisis Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every cohort patient epicrisis reports (three new showcase patients with 8 to 10 woven into a ten-year story, the existing 21 with 5 to 10 background ones), show them in the chart, and let ASKlepios answer from them through one index line per report plus a tool that returns all of them in full.

**Architecture:** The generator writes each report as a DocumentReference with fixed upper-case headings and an `epicrisis` tag (`synthetic/epicrisis.py`). The agent treats a tagged DocumentReference as its own kind of document, reads its fields with plain code (`agent/epicrisis.py`), adds an EPICRISIS REPORTS section to the chart index and a `read_epicrisis` tool. Open loops and medication reconciliation keep reading notes only; surgical history reads the reports. The web app lists them in the Reports tab.

**Tech Stack:** Python 3.12 (FastAPI agent, stdlib generator), React 19 + Vite + TypeScript, HAPI FHIR R4. No unit-test framework exists: deterministic checks are eval modules run with `python -m evals --<name>` that exit 1 on any problem (as `--onboarding` does), the type check is `npm --prefix web run build`, and the model-graded check is the gold set against a baseline.

**Spec:** `docs/superpowers/specs/2026-11-13-epicrisis-reports-design.md`

## Global Constraints

- Base branch: `remove-admission` (not merged into `main`). Work on a new branch `epicrisis-reports` cut from it.
- Every pre-existing resource of the 21 existing patients keeps its id and content. New resources carry `meta.tag` `{"system": "urn:demo:asklepios", "code": "epicrisis"}` and are added after everything a story writes, with random numbers from `random.Random(f"epicrisis:{pid}:{seed}")`, never from the shared sequence.
- Reports are English, generated by plain code, deterministic for a given anchor and seed. No model writes them.
- Nothing from the team's sample report (names, numbers, hospital) appears anywhere. The hospital is "Demo General Hospital".
- In an existing patient a report never introduces a chronic diagnosis, an allergy or a long-term medicine. A discharge prescription lists a long-term medicine only if its order was active on that date.
- Admission ≤ discharge < anchor, and admission no earlier than ten years before the anchor.
- Closed to new operations (medical admissions and diagnostic procedures only): story/variant `diabetes_hypertension/4` (p-1003), `hypothyroidism/0` (p-1014), `diabetes_hypertension/2` (p-1009, apart from its knee replacement report), `chronic_kidney_disease/1` (p-1011, whose hysterectomy gets no report), p-2041 and p-2042 (apart from its ERCP report). The pid for each story/variant is the same at every anchor.
- p-2041's reports never mention a PET scan, an echocardiogram or an ejection fraction.
- No report for an admission that already has a discharge summary note (p-1004, p-1007). No inpatient Encounter resources. No report for p-3001 or p-3002.
- An operation gets a Procedure record (tagged `epicrisis`); a diagnostic procedure (endoscopy, biopsy, fine-needle aspiration, angiography, polyp removal) gets a procedure report but no Procedure record.
- The three existing discharge summaries and operation notes stay notes, untouched.
- Commit messages follow the repository's style (one imperative sentence) and end with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- Gold anchor `2026-10-23`, seed `2041`.

## Review Focus

1. **A patient with no epicrisis reports** (p-3001, p-3002, or any patient on a live server). The index must say none are on file, the tool must say so too, and neither may read as "nothing relevant was found". Pinned in Task 3, Step 1 (`check_none_on_file`).
2. **Reports larger than the tool's size limit.** The newest are returned and the result says how many were left out and from which period; nothing is cut mid-report. Pinned in Task 3, Step 1 (`check_limit`).
3. **A tagged report whose headings cannot be read** (hand-edited, or from a later real source). The index still lists it by title and date with "fields not readable", the tool still returns its text, and the chart index never fails. Pinned in Task 3, Step 1 (`check_unreadable`).
4. **Anchors other than the gold one** (a Saturday, a Monday, 29 Feb). Reports stay inside the ten-year window and before the anchor, and the showcase appointments collide with nobody. Pinned in Task 4, Step 1 and Task 5, Step 1 (the checks run for `2026-10-24`, `2026-10-26` and `2028-02-29`).

```python
class ProcedureReport:
    performed: date
    name: str                      # "Laparoscopic appendicectomy"

    pre_diagnosis: str
    post_diagnosis: str

    drains: str = "None"
    complications: str = "None"
    specimen: str = "None"
    body_site: str = ""
    device: str | None = None

@dataclass(frozen=True)
class Admission:
    title: str                     # "Community-acquired pneumonia"
    admitted: date
    discharged: date
    service: str
    doctor: str                    # display name, e.g. "Dr. Elif Aydın"
    complaint: str
    past_history: str
    examination: str
    course: str
    admission_diagnoses: tuple[tuple[str, str], ...]   # (ICD-10 code, text)
    discharge_diagnoses: tuple[tuple[str, str], ...]
    prescription: tuple[str, ...]
    recommendations: str
    outcome: str                   # "Recovered", "Improved", …
    complications: str = "None"    # during the admission, outside any procedure
    procedure: ProcedureReport | None = None

def text_of(admission: Admission, chart: PatientChart, number: str) -> str
def add(chart: PatientChart, admission: Admission) -> dict   # the DocumentReference; also adds the Procedure when operation
```

- The text is blocks separated by a blank line, each a heading line in upper case followed by its content, as the existing notes are. Exact headings, in order:
  `EPICRISIS REPORT` (followed by the patient line and `Report no. <number> · approved <day> · <service> · <doctor>`), `ADMISSION AND DISCHARGE` (`<day> to <day>`), `COMPLAINT AND HISTORY`, `PAST AND FAMILY HISTORY`, `EXAMINATION ON ADMISSION`, `HOSPITAL COURSE`, `ADMISSION DIAGNOSES` (one `(<code>) <text>` per line), `DISCHARGE DIAGNOSES`, `COMPLICATIONS DURING ADMISSION`, `DISCHARGE PRESCRIPTION` (one per line, or `None`), `DISCHARGE RECOMMENDATIONS AND FOLLOW-UP`, `CONDITION AT DISCHARGE`;
  then, when there is a procedure, `OPERATION REPORT` (or `PROCEDURE REPORT` when `operation` is false) followed by `DATE OF PROCEDURE`, `PRE-PROCEDURE DIAGNOSIS`, `POST-PROCEDURE DIAGNOSIS`, `PROCEDURE PERFORMED`, `TEAM`, `ANAESTHESIA`, `WOUND CLASS`, `OPERATION NOTE`, `ESTIMATED BLOOD LOSS`, `DRAINS`, `COMPLICATIONS`, `PATHOLOGY SPECIMEN`.
- The DocumentReference: id `epi-<pid>-NNN`; `meta` = the synthetic security label plus the `epicrisis` tag; `type` LOINC `18842-5` with text `Epicrisis report`; `description` = `Epicrisis: <title>`; `date` = the discharge day at 16:00; `author` = `[{"display": doctor}]`; `context.period` = admission to discharge; text attachment as notes have. Report number: `ER-<pid digits>-<NNN>`.
- The Procedure (operations only): built with `chart.procedure(...)`, then given the `epicrisis` tag; the DocumentReference's `context.related` references it.

```python
MAX_CHARS = 60_000

@dataclass(frozen=True)
class Epicrisis:
    ref: str
    title: str
    when: datetime                 # the document's date
    admitted: date | None
    discharged: date | None
    service: str
    diagnoses: tuple[str, ...]     # discharge diagnoses, "(I10) Essential hypertension"
    procedure: str | None          # PROCEDURE PERFORMED
    complications: tuple[str, ...] # both complication fields, without "None"
    outcome: str
    readable: bool                 # False when the headings could not be read
    text: str

def reports(record: Record) -> list[Epicrisis]            # newest first
def index_line(report: Epicrisis) -> str                   # ends with " [DocumentReference/…]"
def index_section(record: Record, *, full: bool = False) -> str
def read_all(record: Record, limit: int = MAX_CHARS) -> list[str]   # the tool's blocks
```

- Index section title, lines mode: `EPICRISIS REPORTS, newest first: one line per hospital admission (read_epicrisis returns all of them in full)`; with no reports its only line is `none on file`. Line: `<admitted> to <discharged>, <service>: <title>. Discharge diagnoses: …. Procedure: … | no procedure. Complications: … | none. Condition at discharge: … [ref]`. An unreadable report: `<document date>: <title>. Fields not readable; read_epicrisis for the text [ref]`.
- Full mode title: `EPICRISIS REPORTS, in full, newest first`, each report as the tool gives it.
- Tool `read_epicrisis`, no parameters. Description: `Read every epicrisis report of this patient in full: one per hospital admission, with the discharge summary and, when there was one, the operation or procedure report. Use it before answering anything about earlier admissions, operations, procedures, findings or complications.` First block: `<n> epicrisis reports, admissions from <first day> to <last day>.` Then one block per report, newest first: `[<ref>] Epicrisis report: <title>, <admitted> to <discharged>, <service>` and the full text. Over `limit`: whole reports are dropped from the oldest end and a last block says `<k> older reports were left out (admissions from <day> to <day>).` With none: `No epicrisis reports are on file for this patient.` Label: `Read <n> epicrisis reports`.
- `agent/chat.py`: `Session` gains `specs: list[dict]`; `start_session(session_id, record, extra=None, *, epicrisis_in_prompt: bool = False)` always appends `index_section(record, full=epicrisis_in_prompt)` to the index (before `extra`), and sets `specs` to `tools.SPECS`, without `read_epicrisis` when `epicrisis_in_prompt`. The loop passes `session.specs`.
- System prompt, one new bullet after the SURGICAL HISTORY bullets, exactly:

```

there was one, the operation or procedure report. For any question about earlier admissions, operations, procedures, \
findings or complications, and for any "anything I should know about ..." question, read the reports in full before \
answering: call read_epicrisis, unless the section already gives them in full. Use every report that bears on the \
question and cite each one you use. If none does, say how many reports you read, the period they cover, and that \
none of them mentions it. If the section says none are on file, say that no epicrisis reports are on file. Do not \
read them for questions about current results, medicines or orders.
```
